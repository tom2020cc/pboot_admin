Google 服务账号 JSON 怎么获取？点开看详细步骤
  1. 用拥有本网站 Search Console 权限的 Google 账号，打开 Google Cloud Console（console.cloud.google.com）。
  2. 点页面顶部的项目选择器 →「新建项目」，名称随意（例如 shanbo-search-console），创建后切换到该项目。
  3. 左侧菜单「API 和服务」→「库」，分别启用 Search Console API 和 Indexing API。
  4. 左侧菜单「IAM 和管理」→「服务账号」→「创建服务账号」。名称随意（例如 shanbocc），角色可以不选，一路「完成」。
  5. 在服务账号列表中点进刚建的账号 →「密钥」标签页 →「添加密钥」→「创建新密钥」→ 类型选 JSON →「创建」。浏览器会自动下载一个 .json 文件，这就是服务账号 JSON。
  6. 打开 Search Console，把 JSON 里的 client_email 加入当前属性。Search Console 数据至少需要完整权限；Google 的 Indexing API 官方流程要求该服务账号成为站点所有者。漏掉授权或选错属性通常会报 403。
  7. 用记事本打开下载的 JSON 文件，全选、复制，粘贴到上方输入框，点「保存并验证服务账号」。看到取得 Indexing API 访问令牌即配置成功。

01

创建或选择 Cloud 项目

用拥有网站 Search Console 权限的 Google 账号登录 Cloud Console。新建项目后切换到该项目，后续服务账号、API 和配额都必须在同一项目内。

02

启用两个 API

打开上方两个 API 直达页，确认项目名正确后点击“启用”。配置完成时页面按钮会变成“管理”或“停用 API”；只启用其中一个会导致部分按钮返回 403。

03

创建服务账号与 JSON

进入“服务账号”，点击“创建服务账号”。项目角色可以跳过；创建后依次进入“密钥 → 添加密钥 → 创建新密钥 → JSON”，密钥文件只会下载一次。

04

给站点授予权限

打开 Search Console 并选中目标属性，进入“设置 → 用户和权限”，添加 JSON 中的 client_email。若 Indexing API 仍返回 403，再核对该账号的所有者状态。

05

导入 JSON 并验证

用记事本打开 JSON，全选复制到上方服务账号输入框，点击“保存并验证服务账号”。成功后账号邮箱会显示在页面右侧，输入框会自动清空。

06

配置 Search Console 属性

域名属性填写 sc-domain:example.com；网址前缀属性必须包含协议和末尾斜杠。Sitemap 地址必须属于同一属性，保存后先读取 Sitemap 状态。

07

按正确方式推进收录

普通产品页以 Sitemap、内部链接和 Search Console 手动请求为主。Indexing API 官方仅支持含 JobPosting，或 VideoObject 中 BroadcastEvent 的页面，不应把普通产品页当作批量强推接口。

08

配额与断点续传

Indexing API 初始默认发布配额为 200 次/项目/天，并在太平洋时间零点重置。本工具会记录成功 URL 和今日用量，恢复网络或配额后只处理剩余列表。

换站部署清单

每个 PbootCMS 网站使用自己独立的一份工具目录和配置，互不共用数据库、端口、FTP 或 IndexNow Key。

1. 独立放置

  • 把完整工具目录复制到新网站自己的根目录。
  • 不要直接共用另一个站点正在运行的工具目录。

2. 项目配置

  • 在项目配置页填写新网站根目录、SQLite 数据库、独立端口。
  • 填写本地测试地址和真实线上地址。

3. 发布配置

  • 在 FTP 页面填写该网站自己的 FTP 信息。
  • 为该网站单独生成 IndexNow Key，禁止跨站复用旧配置。

4. 上线验证

  • 生成并上传 SEO 文件后检查线上 sitemap 与 robots。
  • 到对应站点的 Search Console 提交 sitemap。
