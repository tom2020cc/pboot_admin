Google 服务账号 JSON 怎么获取？点开看详细步骤
  1. 用拥有本网站 Search Console 权限的 Google 账号，打开 Google Cloud Console（console.cloud.google.com）。
  2. 已有服务账号和 JSON 可以复用；没有时再点顶部项目选择器 →「新建项目」（例如 shanbo-search-console）。共享账号配置完成后，其他网站无需再次粘贴 JSON。
  3. 左侧菜单「API 和服务」→「库」，启用 Search Console API。普通产品和新闻不需要 Indexing API。
  4. 左侧菜单「IAM 和管理」→「服务账号」→「创建服务账号」。名称随意（例如 shanbocc），角色可以不选，一路「完成」。
  5. 在服务账号列表中点进刚建的账号 →「密钥」标签页 →「添加密钥」→「创建新密钥」→ 类型选 JSON →「创建」。浏览器会自动下载一个 .json 文件，这就是服务账号 JSON。
  6. 打开 Search Console，把 JSON 里的 client_email 加入当前属性。Search Console 数据至少需要完整权限；Google 的 Indexing API 官方流程要求该服务账号成为站点所有者。漏掉授权或选错属性通常会报 403。
  7. 打开 JSON 文件，粘贴到上方并保存。选择本网站的 Search Console 属性，点击测试，确认属性权限正常；只有取得令牌不代表有站点权限。

使用教程新网站复用账号：按 7 步操作

以后添加新网站，照这 7 步做

共享账号：本系统已经存好 Yandex 的通行凭证（Token），新网站不用再申请、复制一份。单独验证：每加一个新域名，要向 Yandex 证明这个网站是你的。

例如：山博的 ru.shanbo-rig.com 已经做好了；以后新增 ru.example.com（仅为示例），共享同一个账号，但新域名仍要验证一次。日常更新内容不用重复验证。

  1. 先切换到新网站。在管理后台选中要操作的网站，设置好“区域管理”中 RU 的线上域名，再打开这个网站的“SEO 检查 → Yandex”。新网站需已上线，发布连接也已配置。
  2. 确认已经共用账号。展开本页“账号与俄语站配置”，看到“共享账号已配置”就不用填 Token，也不用再点“保存配置”。如果该站原来用专用账号，点击“使用已有共享账号”。
  3. 去 Yandex 添加新域名。点击“打开 Yandex 添加 / 验证网站”，用取得共享 Token 的同一个账号登录，点击 Add，填写新网站完整地址，例如 https://ru.example.com/。不要填旧网站地址，HTTP 与 HTTPS 也要一致。
  4. 保存这个新网站的验证文件。在 Yandex 选择 HTML file 验证方式，下载并打开它提供的文件。回到本页展开“使用 HTML 验证文件”，填入文件名和完整文件内容，点击“保存验证文件”。使用新网站这次给出的内容，不要直接照抄山博的示例。
  5. 上传后回 Yandex 验证。点击第 1 步“先：生成并上传”，等上传完成，再回 Yandex 点击 Verify / Check。看到验证通过或 Owner 才算完成。如果已用 DNS 或标签验证通过，第 4、5 步可跳过。
  6. 回本页测试权限。点击“测试俄语站权限”，应显示“俄语站权限已通过”。如果提示没有网站或未验证，先核对登录账号、完整域名和上一步结果，不要反复申请 Token。
  7. 开始提交。文件未生成上传时先点“先：生成并上传”，然后点“再：提交网站地图”。内容有更新时点“通知俄语站页面”。成功后等待抓取，过几天再看结果，不必逐个提交页面。

如果显示“共享账号尚未配置”：确认打开的是原来配置过的这套管理系统。另一台电脑或线上管理后台不会自动获得本地密钥；线上可在“网站发布 → 代码与配置同步 → 项目配置同步”勾选“Google / Bing / Yandex 共享账号”后同步，再刷新页面。

第一次使用本系统、还没有共享 Token 时

在 Yandex OAuth 创建 API 应用，选择 webmaster:hostinfo 和 webmaster:verify 权限。确认授权账号与 Webmaster 管理网站的账号相同，授权后在本页粘贴 Token，勾选“保存为共享账号”，点击“保存配置”。配置一次即可，后续新网站按上面 7 步操作。

当前功能只提交 RU 站，其他语言站不会混入。OAuth 账号可能管理多个站点，每个项目仍需分别验证。

02
启用 Search Console API
打开 Search Console API 官方入口，核对项目名后点击“启用”。页面显示“管理”或“停用 API”即已启用。钻机、挖掘机产品及一般新闻不需要 Indexing API。

          
03
创建服务账号与 JSON
进入“服务账号”，点击“创建服务账号”。项目角色可以跳过；创建后依次进入“密钥 → 添加密钥 → 创建新密钥 → JSON”，密钥文件只会下载一次。

          
04
给站点授予权限
网站所有者先在 Search Console 验证目标属性，再到“设置 → 用户和权限”添加 JSON 的 client_email 并授予完整权限。受限用户只能读取部分信息，不能提交 Sitemap。

          
05
导入 JSON 并验证
用记事本打开 JSON，全选复制到上方服务账号输入框，点击“保存并验证服务账号”。成功后账号邮箱会显示在页面右侧，输入框会自动清空。

          
06
配置 Search Console 属性
域名属性填写 sc-domain:example.com；网址前缀属性必须包含协议和末尾斜杠。Sitemap 地址必须属于同一属性，保存后先读取 Sitemap 状态。

          
07
按正确方式推进收录
普通产品页以 Sitemap、内部链接和 Search Console 手动请求为主。Indexing API 官方仅支持含 JobPosting，或 VideoObject 中 BroadcastEvent 的页面，不应把普通产品页当作批量强推接口。

          
08
验证结果与日常优化
检查线上 Sitemap 和 robots，提交 Sitemap 后读取处理状态，再抽查重要 URL 的索引状态。优先修复 noindex、重复 canonical、失效链接和语言对应关系；增加真实产品信息，不堆砌关键词。

        

        

          常见问题快速判断
          
API 未启用确认服务账号所在 Cloud 项目已启用 Search Console API，启用后稍候再试。普通网页无需开启 Indexing API。

          
403 / 权限不足检查服务账号邮箱是否被添加到当前 Search Console 属性，并具有所有者或完整权限。

          
属性不匹配域名属性使用 sc-domain:，网址前缀属性要严格匹配协议、子域名和末尾斜杠。

          
达到配额或断网保留已有检查记录，等待配额恢复后继续诊断。提交 Sitemap 没有“立即收录”保证，不要用重复通知代替内容与可抓取性优化。

换站部署清单

            
每个 PbootCMS 网站使用自己独立的一份工具目录和配置，互不共用数据库、端口、FTP 或 IndexNow Key。

          

          
        

        

          
1. 独立放置
  • 把完整工具目录复制到新网站自己的根目录。
  • 不要直接共用另一个站点正在运行的工具目录。

          
2. 项目配置
  • 在项目配置页填写新网站根目录、SQLite 数据库、独立端口。
  • 填写本地测试地址和真实线上地址。

          
3. 发布配置
  • 在 FTP 页面填写该网站自己的 FTP 信息。
  • 为该网站单独生成 IndexNow Key，禁止跨站复用旧配置。

          
4. 上线验证
  • 生成并上传 SEO 文件后检查线上 sitemap 与 robots。
  • 到对应站点的 Search Console 提交 sitemap。
