# 数据库改名与同步

## 只同步区域配置

入口：本地管理后台「区域管理 → 同步区域配置到线上」，或「网站发布 → 数据库 → 区域配置」。首次更新此功能后，需重启本地网站发布工具以加载新接口；旧服务会在页面提示重启并禁用操作。

1. 先选择正确的网站，点击「读取并预览」。使用该项目已保存的宝塔连接，通过站点编码匹配线上网站，并核对线上站点档案与 PB 数据库路径。
2. 对照页面中的线上当前值、本地同步值及目标数据库路径。点击「确认同步到线上」执行，无需重复弹窗确认。
3. 等待「区域配置同步完成」，刷新线上区域管理。同步成功会清理 PB 缓存。

范围仅为当前 PB 数据库 `ay_area` 的顶级语言区域：按 `acode` 匹配，更新名称、域名（含空值）和默认语言；缺少的语言新增，原有 ID 保留。线上独有语言保留，但默认语言统一为本地指定的一个。新增语言并不同时发布内容。

产品、文章、模板、账号、授权、询盘及 `ay_site` 配置不变，不改表结构，不复制整库，不修改 DNS、Nginx 域名绑定或证书，不自动创建备份。域名解析及证书另用「域名上线检测」核对。

预览有效期 10 分钟；站点、连接配置或两端区域发生变化须重新预览。重复域名、无效域名、本地测试域名、默认语言数量异常、编码冲突均拒绝写入。事务内逐项核验，不一致会回滚。执行期间沿用数据库维护机制短暂暂停并恢复管理后台及内容任务，避免管理端写库覆盖；PHP 前台不停止。

区域操作通过已有宝塔通道在内存中运行本地 `deploy/database-actions.py`，不要求先向线上部署新版管理代码，也不在服务器覆盖该脚本。普通数据库同步仍保持原规则：保留线上区域域名及默认语言。

本地验证：6 项 SQLite 区域测试、原有 13 项数据库测试及 Node 发布流程测试通过，覆盖空值、新增、保留区域/ID/业务数据、重复执行、两端过期预览、跨站点拒绝与回滚。此次添加功能没有执行真实线上同步。

从本地「网站发布 → 数据库改名与同步」进入。页面分别显示管理后台数据库、当前 PB 网站数据库；线上环境隐藏这些操作，接口也拒绝从线上发起。

1. 点击对应区域的「读取线上数据库」，核对本地源路径与线上目标路径。
2. 改名：填写新的 `.db` / `.sqlite` / `.sqlite3` 文件名，点击「重命名线上数据库」。只改线上名称，不改本地库；目标名称已存在会拒绝覆盖。
3. 同步：点击「同步数据库到线上」。上传临时快照并核对 SHA256，按现有表结构在事务中覆盖业务数据，空字符串同样覆盖。已有表单缺少的可空文本字段可在事务内补齐，其他表结构不一致时拒绝。图片、模板文件另行上传。

管理库同步保留线上 `managed_sites`、账号和自动任务运行配置，按站点编码匹配站点 ID；两端站点编码列表必须一致。PB 库保留线上系统配置（含授权码）、账号、区域域名、默认语言、站点域名及模板绑定。线上询盘留言及自定义表单提交数据保留；已有表单按 fcode 匹配，同步表单定义和字段配置。线上独有表单保留；编码与数据表不匹配或新表单尚未在线上建立时停止。

管理库同步覆盖全部站点、全部语言的业务记录，完成后逐表核验实际内容（包含空值和站点 ID 映射），内容不一致会回滚事务。页面显示完成时间、每张表的记录数量及内容核验结果。保留线上 `site_information_draft`：这张表的域名、模板及 `baseRevision` 依赖当前环境的 PB 数据，不能直接复制本地草稿来替代专用的站点资料同步。

管理库同步完成不等于前台网站已经发布。区域管理和产品字段保存在 PB 数据库，产品等管理内容仍须通过对应的「同步网站」写入 PB；图片和模板仍需文件上传。管理库同步不会修改 PB 数据库、系统授权码或服务器域名绑定。

需要更新各语言的站点域名和模板选择时，使用「站点与公司信息 → 同步到线上」；此入口会核对线上域名及模板目录，并写入这两项，空值也会覆盖。

改名管理库会同步修改 `backend/.env` 中的 `DB_SQLJS_LOCATION`；PB 改名会同步修改网站 `config/database.php` 和管理库中对应站点的 `dbPath`。改名失败会恢复原文件名与配置。操作期间停止管理后端及已运行的内容任务进程，结束后恢复；PB 改名还会暂停对应 PHP 服务，确认框会显示受影响的网站数量。

数据库操作通过已有宝塔登录会话协议及 FTPS 执行，不新增账号或开放端口，不修改 Nginx 配置，不自动创建备份。读取目标的确认凭据有效期为 10 分钟，切换站点或连接配置后须重新读取。执行脚本为 `deploy/database-actions.py`，普通代码同步会将它部署到线上。

验证：SQLite 临时库测试覆盖空值、账号与域名保留、站点 ID 映射、重名冲突、配置改名与失败回滚；浏览器隔离测试覆盖两个入口、PHP 维护提示及线上按钮隐藏。正式数据库的改名/覆盖须在页面核对目标后由使用者明确执行。
