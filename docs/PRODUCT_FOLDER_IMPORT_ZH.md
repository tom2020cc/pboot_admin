# 产品文件夹与参数导入

入口：添加产品 → 文件夹批量导入。选择资料目录、目标中文产品栏目，参数类型通常保持“按型号资料”（原“自动识别”），点击“扫描资料目录”核对后导入。

## 宝塔服务器目录与缩略图尺寸

- 顶部区分“服务器目录”与“本机后台目录”，显示后台连接地址和当前网站；本功能读取后台磁盘，不是上传浏览器电脑中的文件。环回地址表示本机后台连接；自行设置远程代理时以实际后端机器为准。
- “当前导入目录”显示完整层级，突出最后一级，并标注相对网站根目录的层数。右侧单独显示目标网站、中文 CN 和栏目完整父子路径；目录名称不会自动匹配栏目。
- “浏览位置”与已选中的导入目录分开显示。进入子目录但未点“使用此目录”时标为“浏览中，未选用”，不会暗中改变实际来源。确认导入弹窗再次列出完整目录和目标栏目。

1. 当前网站需在“站点管理”配置真实 `rootPath`。打开批量导入时，后端读取这个网站的服务器根目录，首次自动填入资料目录；不是读取浏览器所在电脑的磁盘，也不是管理后台自身的目录。
2. 点击目录右侧房屋图标可重新使用网站根目录；文件夹图标打开服务器子目录选择器。进入 `static` 下实际存放型号资料的目录，点击“使用此目录”。根目录处不能继续向上；只显示普通非隐藏文件夹，不提供其他网站或服务器系统目录浏览。
3. 仍可手动填写后端所在机器的绝对路径。服务器部署后使用 Linux 路径，例如 `/www/wwwroot/your-site/static/Rigs`，电脑上的 `E:\...` 不会被上传或自动映射到宝塔。站点资料位于其他服务器时，先部署到后台可读取的目录，不能通过域名读取远端文件系统。
4. 在“缺少 0.jpg 时生成的缩略图”设置宽、高，默认 **500×400**，每边支持 **64–4096 整数像素**。只作用于本次批量导入缺少缩略图的型号，不改变新闻或单张上传的默认尺寸。改变尺寸后要重新扫描。
5. 已有 `0.jpg`（包括 `0.JPG`）就直接使用，文件内容、尺寸和修改时间保持不变。只有缺少时才由 `1.jpg` 生成指定大小的 JPEG，等比例缩放、居中补白，保存到该型号原目录；不裁切、不拉伸、不改原图。
6. 浏览目录、填写尺寸和扫描均不创建文件、不写数据库。确认导入后才生成缺少的缩略图；缺少源图或损坏源图的处理沿用下文规则。重新扫描时再次检查现有 `0.jpg`，并发导入也不覆盖已经生成的文件。

目录不存在、权限不足或路径超出当前网站时会显示错误，输入的路径不被清空。应在宝塔检查真实目录和后台进程的读取权限，而不是把项目改为 `777`。本功能不批量修复旧图片、不改旧产品数据。

每个型号一个文件夹。TXT 与 HTML 只要对应型号即可，不要求固定后缀，例如：

```text
Portable Core Drilling Rig/
  CR600P/
    CR600P_标题 (1).txt
    CR600P_index(2).html
    0.jpg
    00.jpg
    1.jpg
    2.jpg
    3.jpg
    4.jpg
    01.jpg
    02.jpg
```

`CR600P参数.txt`、`CR600P详情.html`、`CR600P.html` 也可识别，英文大小写不影响匹配。也支持直接选择一个型号文件夹。同型号多份 TXT 的相同值会合并，不同值会提示核对；不会将 CR600P1 当成 CR600P。

## 岩芯钻机

在型号对应的 TXT 中，每行写一个参数：

```text
产品型号：CR600P
钻探深度（m）：600
取芯能力（m）：BQ 760 / NQ 600 / HQ 280
提拔力（kN）：100
```

对应关系：

| 资料参数 | 项目中的目标 |
| --- | --- |
| 钻探深度 | 钻孔深度，`ext_drill_depth` |
| 取芯能力 | `ext_core_capacity`，完整字符串 |
| 提拔力 | 优先匹配已启用的“回拉力 / 提拔力 / 提升力”字段 |

当前山铂鼎钻机站点的回拉力字段为 `ext_param_7801907f4e874d29`。程序根据当前站点配置匹配，不把这个名称写死给其他站点；不会把提拔力填到发动机，也不会恢复已移除的旧回拖力字段。

## 水井钻机

同样放在型号对应的 TXT 中，中英文标签均可：

```text
Drilling Depth: 600 m
Drilling Diameter: 105–450 mm
Rotary Torque: 12,000 N·m
```

保存为深度 `600`、直径 `105-450`、回转扭矩 `12000`，单位分别为 m、mm、N·m。扭矩使用独立字段，不会写入回拉力或发动机。缺少对应字段时，确认导入会在本项目的当前站点配置中创建，并自动补齐当前 PB 网站的原生扩展字段，无需再手动点“同步字段到 PB”。

## 自定义三参数

参数类型保持“按型号资料”。每个型号独立读取自己的三项参数，不再强制套用岩芯、水井的三项组合；同样适用于挖掘机等其他网站。建议在 TXT 写出“产品参数”标题和三行数据，例如：

```text
产品型号：EX100
产品参数：
发动机功率（kW）：85
整机重量（kg）：10000
铲斗容量（m³）：0.4
SEO标题：EX100 产品介绍
```

1. 每个产品最多导入三个实际参数，按 TXT 中首次出现的顺序取前三项。型号间参数组合可以不同，不因为看到钻孔直径就把第三项替换成回转扭矩。超过三项提示，第四项及以后不导入；不足三项留空，不补示例值。
2. 无单位的参数必须放在“产品参数 / 参数 / Specifications”段落内，例如 `发动机：Cummins`；有单位时写在名称括号中。SEO 标题、关键词、描述等不会作为参数。不要把正文长表格放进此三参数段落。
3. 扫描只显示结果，不创建字段、不修改 PB。确认导入时，按当前站点的参数名称（含既有别名）与单位共同匹配；同名同单位、已启用的文本字段复用，没有完全匹配的才新建独立字段。同名不同单位并存，不覆盖原字段单位或数值；同名同单位字段停用或有多个匹配仍需核对，不擅自启用。
4. 自动同步的是本次三项所需的 PB 字段定义和缺失的扩展列。已有字段及产品值不覆盖，其他站点不受影响。重复型号仍跳过；重复字段不创建，不重复备份无变化的 PB 数据库。
5. 产品参数值先保存在新建的中文产品中。之后正常“同步网站 / 同步到 PB”时，与产品一起写入对应原生字段，并沿用共享参数的多语言同步流程。不会自动发布产品、批量修改旧产品或改写网站模板。

例如 WR400RC 的 TXT 是深度 `400 m`、直径 `105-305 mm`、提升力 `40 T`，三项原样保留。网站原有“回拉力 / 提升力（kN）”不变，新建“提升力（T）”字段；下一个型号也是提升力 T 时复用新字段，各型号只保存自己的值。不会自动换算 T 和 kN。不同单位的钻孔深度也写入独立字段，不将英尺数值写进米字段。

“岩芯钻机”“水井钻机”仍为手动固定模板；主动选择后按原单位和组合校验。资料实际组合不同时使用“按型号资料”。同一份资料将名称单位写成 kN、数值却附带 T，或同一型号多份 TXT 给出冲突数值，依然报错，不能用新字段掩盖源数据冲突。

在扫描表中检查“本型号参数 / 对应字段”“复用同名同单位字段”“将新建独立字段并同步 PB”，确认名称、单位、值正确后再导入。PB 数据库不可写或字段冲突会在该型号的失败原因中显示；解决后重新扫描导入。新建的本地字段会保留供重试复用，不为每个型号重复创建同名同单位字段。PB 字段定义随确认导入补齐，产品值仍需正常同步网站；前台写死字段名的模板不会自动改写。

## 核对与保存

- 扫描会显示来源 TXT、识别的数值、对应字段，以及是否需要新建字段；扫描本身不修改产品或 PB 数据库。
- TXT 中其他 SEO 标题、关键词等文本不会被当成参数执行；产品标题仍采用文件夹型号名。
- 参数缺失就留空，不将示例值当成真实规格。水井产品不会自动补岩芯取芯能力。
- 源资料本身单位矛盾、同一参数出现多个不同数值、同名同单位字段停用或无法唯一匹配时，提示核对并跳过该型号。与已有字段单位不同不再报错，而是单独建字段；不会自动换算 T 与 kN。
- 缩略图用 `0.jpg`；缺少时，在正式导入该型号时由 `1.jpg` 按本次设置生成 JPEG（默认 **500×400**），保存在原型号文件夹，原图不变。按比例缩放、居中补白，不裁切或拉伸。已有 `0.jpg`（大小写不敏感）直接保留，不重新生成。兼容编号 `1` 的 PNG、WebP、JPEG 图片。
- 扫描显示“待生成”，不写入文件。没有编号 `1` 的图片时不自动拿其他图片生成；保留原有缺图回退规则。损坏、超大或无法读取的源图片会让该型号导入失败并给出原因，其他型号继续处理。
- 大图 `00.jpg`，轮播 `1.jpg` 至 `4.jpg`，详情插图 `01.jpg` 起。这些图片的尺寸不变。
- 详情插图保持编号顺序 `01 → 02 → 03`，随机选择正文标题前的位置，再按正文先后依次放图。标题够用时一处一张；标题不足时均匀分配，无标题时按顺序追加到正文末尾。仅在导入时生成位置，保存后不会随刷新或翻译重新随机排列，不修改已有产品。
- 一个型号只保存一份共享参数。创建时只有中文内容，其他语言仍需翻译；已有译文的产品同步时共享相同参数。
- 导入先备份项目数据库；同一中文栏目下的同名型号会跳过，不覆盖已有产品。
- 导入只创建项目产品，**不会自动发布 PB 产品**，不改 PB 核心文件或模板。

## 图片地址

- 资料放在当前选中网站的 `static` 目录内时，直接保存原图片的 `/static/...` 地址，不复制图片，也不创建新的导入图片目录。缩略图、大图、轮播图、详情插图均使用这一规则，新闻文件夹导入同样适用。
- 例如 `E:\phpstudy_pro\WWW\shanbo-rig.c\static\Drilling Rigs\Core Drilling Rig\CR600P\0.jpg` 直接引用原文件；路径中的空格、中文等按 URL 编码，目录名和文件名大小写不变。
- 当前网站以项目顶部选中的站点配置为准。来自其他网站或站外资料目录的图片，仍复制到当前网站的 `static/codex/folder-import/...`；新闻使用 `static/codex/news-folder-import/...`。非公开目录也保留复制流程。
- 操作步骤不变，扫描不复制文件。导入后可以在原目录替换同名图片，但不要随意移动或删除已引用的图片。
- 此规则只影响后续导入；已导入记录和旧图片不会自动迁移或删除，同栏目重复型号仍按原规则跳过。

## 手动上传产品缩略图

- 新产品先选中文产品栏目、填写中文型号 / 标题，再上传缩略图。编辑已有产品时使用已保存的产品型号和站点归属定位目录。
- 优先使用该型号已有图片所在的 `static` 子目录；其次查找站点 `static` 下与型号对应的目录。重名目录无法确定时提示核对，不随便写入另一个目录。
- 尚无型号目录时，建立 `static/codex/product-images/栏目ID/型号/`。返回可移植的 `/static/...` 图片地址，不保存 Windows 绝对路径或 localhost 地址。
- 上传后生成500×400 JPEG，文件名为 `thumbnail-随机编号.jpg`。每次另存，不覆盖 `0.jpg`、原图或上次缩略图；点击“保存修改”后产品才引用新缩略图。
- 此处理用于产品的“缩略图”上传，新闻缩略图也使用同样规则；产品大图、轮播图和正文图片仍保持原上传方式。手动填写图片地址不自动处理已有图片。
- 上传源文件最大5MB，文件夹源图最大30MB；解码限制4000万像素，接受 JPEG、PNG、WebP、GIF（首帧）。不接受 SVG 等文档格式。含透明背景的图片补白，带旋转方向信息的照片自动转正。
- 当前站点的图片目录必须可写。宝塔部署时在 Linux 服务器重新执行 `pnpm install --frozen-lockfile` 安装 Sharp 对应平台依赖，不复制 Windows 的 `node_modules`；Node.js 版本沿用项目要求，给 Node 服务用户授予该站点 `static` 目录的必要读写权限即可。

缩略图自动化测试使用临时目录和合成图片，不批量改动现有产品图片。
