# 网站发布：文件管理与覆盖上传

## 两个入口

- **① 管理项目代码与配置**：管理项目账号对应管理项目根目录；源码发布与配置迁移分开操作。配置迁移需主动勾选，线上数据库不直接覆盖，`system-license.json` 始终保留线上版本。本地 FTP 网卡设置不随配置迁移到 Linux。
- **② 当前网站文件同步**：左侧根目录来自当前所选站点，右侧使用该站点自己的 FTP 账号。高级批量范围（数据库、图片、SEO、整站）收起放置，日常使用左右文件栏。

## 2026-09-22 连接修复

本机 FlClash 虚拟网卡接管默认路由时，FTP 控制连接在收到欢迎信息前关闭。绑定物理网卡后，管理项目与网站两个账号均成功完成读取目录、上传临时文件、下载校验、同名覆盖及清理。

连接配置新增「连接网卡」，当前机器选用已验证的有线网卡。适配层只为该 FTP 客户端的控制和被动数据连接绑定本地地址，不修改 Windows 路由、系统代理或全局 Socket。网卡地址运行时解析，网卡不存在时会明确报错。移到别的电脑应重新选择或使用系统默认。依赖 basic-ftp 5.x 的 `_newSocket` 工厂，同时有控制/数据连接回归测试；升级该依赖时需要重新验证。

此次无需修改宝塔防火墙或 FTP 服务配置。远程临时验证文件已清理，未批量覆盖业务文件。

进入「网站发布」，在「文件管理 · 选择覆盖上传」功能块操作：

1. 左侧自动读取顶部当前站点的根目录，可进入子目录、返回上层，勾选文件或目录，跨目录选择会保留。
2. 右侧点击「读取远程目录」，使用本页已保存的 FTP 配置浏览远程目录。修改上方连接信息后，先保存配置。
3. 点击「预览所选上传」，核对站点、本地根目录、FTP 目标、完整文件清单与排除项。
4. 点击「确认覆盖上传上述文件」。目录递归展开，重复选择去重；空目录不单独上传。上传进度和错误同时显示在功能块与发布日志中。

远端位置始终是已保存的 FTP 根目录加文件在本地站点中的相对路径，右侧浏览位置不会改变上传目标。例如 `template/cn/index.html` 上传到 `<FTP根目录>/template/cn/index.html`。沿用原发布工具语义，FTP 根目录相对于 FTP 登录目录。

此功能直接覆盖同路径文件，不跳过同大小图片、不创建备份，也不删除远端其他文件。默认排除 PB 的 `data`、`config` 与数据库文件，保留线上数据、域名和授权码；确需覆盖时，先勾选「包含数据库与环境配置」，再重新选择与预览。缓存、管理项目、`.env`、私钥、备份压缩包等始终排除。

服务端限定当前站点根目录，拒绝目录穿越与符号链接。确认计划绑定当前站点、FTP 配置与本地文件状态，有效期十分钟且只能使用一次；文件或连接配置改变后须重新预览。与既有发布、同步和巡检任务互斥。浏览及预览不会上传，实际上传仅由确认按钮发起。

验证：`node --test tools/ftp_publish_tool/file-browser.test.js`；界面隔离测试 `node tools/verify-file-browser.cjs` 使用模拟 API，不连接真实 FTP。

## 模板与功能代码一起同步（2026-09-24）

线上原样显示 `[list:product_specs]`，说明标签没有被解析。此次实际核对：线上产品列表有 41 处原样标签；缺少 `ProductSpecsRenderer.php`、`product-spec-labels.json`，`ParserController.php` 和 `ParserModel.php` 也未包含新功能。仅上传模板无法补齐这些代码，不需要为此覆盖数据库。

在「② 当前网站文件同步」点击 **预览模板同步（含功能代码）**，核对目标与清单，再点击 **确认覆盖上传上述文件**。该快捷按钮只选 `template/`，关闭数据库与环境配置覆盖；检测到产品属性标签或公共模板引用时，自动加入以下依赖：

- `apps/home/controller/product-spec-labels.json`
- `apps/home/controller/ProductSpecsRenderer.php`
- `apps/home/model/ParserModel.php`
- `apps/home/controller/ParserController.php`

手动选择模板、或高级上传通过 `extraPaths` 包含模板时，也执行相同检查。当前自动识别范围是产品列表属性功能；其他自定义标签需补充依赖规则。

先上传字典、渲染器、数据读取方法和解析器，逐个回读 SHA-256 校验后再传模板。缺失、被排除或版本不匹配的本地依赖会阻止预览；预览后依赖变化需要重新预览。校验失败会停止上传。依赖代码不会因为大小相同而跳过。

更新本地工具代码后需重启网站发布服务。旧服务缺少依赖检查版本标识时，页面会阻止模板上传并提示重启，避免新按钮调用旧逻辑。

传输完成后刷新线上产品列表验收；如文件校验一致但页面仍旧，到 PB 后台清理缓存，必要时由管理员检查 PHP OPcache。文件传输完成不等于页面验收完成。经用户明确确认“现在补传并验证”后，已使用修正后的本地上传模块补传上述 4 个依赖，SHA-256 回读全部通过，未上传数据库、环境配置或其他模板。线上 `/Drilling-Rigs/` 返回 HTTP 200，原样标签从 41 处降为 0，显示 123 行属性；`/Solar-Pile-Driver/` 同样返回 HTTP 200，无原样标签，显示 9 行属性，浏览器与用户均确认恢复。自动审批两次拦截本地发布服务重启，未返回具体原因，因此 5389 上的既有进程仍需重启后加载新依赖检查；新版前端会阻止旧服务生成模板上传清单。
