# 产品生成PDF（多语言完整详情）

## 入口和操作

管理后台顶部“产品生成PDF”，地址仍为 `/#/brochures`。

1. 选定当前站点和“产品语言”，点击“从产品库导入”。列表显示目标语言栏目和翻译状态，读取所选语言的完整产品详情；也可手动添加空白产品。
2. 在“产品详情正文”编辑整个 HTML 字段，任意增删文字、图片、原文表格。新导入不再额外提取或生成参数表；旧资料参数留在折叠区，可确认后移除。正文开关可排除内容但不删除；清空和重新读取都有确认。
3. 图片和产品可以调整顺序。新导入默认读取产品大图和轮播图，不额外加入缩略图；第一张为主图，其余按顺序每行两张，最后落单的一张独占一行。支持上传、替换、删除引用和填写图片说明，详情编辑器也能插入图片。图片按原比例完整展示。旧资料和手动选图保持不变。
4. 点击“保存资料”。已保存资料支持查找、重开、修改、另存为和删除。
5. “打开网页”在新窗口展示；“下载 HTML”导出包含图片的独立网页文件，可离线查看或放到自己的服务器上。
6. “导出 PDF”直接下载 PDF 文件，不再打开系统打印窗口。浏览器用 Paged.js 完成分页，再交给本项目后端的 Playwright / Chromium 输出 PDF，不调用付费服务，不把产品资料交给第三方网站。

## 固定分页与版面

- 编辑工作区撑满浏览器宽度，保留两侧操作留白；桌面编辑与预览各占一半，窄屏上下排列。独立网页最大宽度仍为 1500px，小屏幕等比例缩小，不横向溢出。
- 纸张固定为 A4 纵向（210mm × 297mm）。屏幕以 1500px 宽度展示整张纸时，单页约 2121px 高；PDF 始终保持真实 A4 尺寸。
- 正文超出当前页自动续到下一页，表格续页重复表头；默认下个产品从新页开始，也可关闭此开关。页码显示当前页 / 总页数，预览显示总页数。主图尺寸可选大图或适中。
- 主图单独全宽；附图两列，奇数最后一张全宽。每组图片作为一个分页单元，放不下时整组移到下一页，不把同一组拆成两个半行。按原比例完整显示，不裁切产品；正文里的图片和表格保持原文顺序，不混入附图分组。
- 下载的 HTML 已完成分页并内嵌图片，离线打开不需要 CDN、Paged.js 或外部图片服务。页面仅附带本地尺寸适配脚本。

## 字号、行距和原文表格

“PDF 排版”只影响当前资料的网页预览、HTML 和 PDF，不改产品库或 PB 网页，也不重新提取参数。

| 设置 | 默认 | 可调范围 |
| --- | --- | --- |
| 正文字号 | 11pt | 9–16pt |
| 正文标题字号 | 16pt | 12–24pt |
| 正文行距 | 1.6 倍 | 1.2–2.2 倍 |
| 段落间距 | 6pt | 0–16pt |
| 表格字号 | 10.5pt | 8–14pt |
| 表格行间距 | 标准 | 紧凑 / 标准 / 宽松 |
| 表格样式 | 网页浅蓝 | 网页浅蓝 / 简洁横线 / 清晰网格 |

1. “字体高度”使用行距调节，不给文字块固定高度。正文标题设置作用于详情中的 H1–H6 层级，产品型号、封面标题、页眉页脚保留自己的尺寸。
2. 推荐从正文 11–12pt、行距 1.6–1.8、表格 10.5–11pt、标准间距开始。字号或间距变大，内容自动重新分页，页数可能增加。
3. 网页浅蓝样式参考产品网站：浅蓝表头和分组栏、细边框、正常字重的参数值。简洁横线适合文字较多的说明；清晰网格适合多列表格。
4. 保留原文表格、合并单元格、文字强调和图片。没有 THEAD 但首行全为 TH 的普通表格，输出副本会规范为表头并在续页重复；全宽 TH 分组尽量与下一行同页。复杂嵌套表格不猜测表头，超长内容需预览核对。
5. 清空数值输入会恢复该项默认值；右上角重置图标仅重置排版，不删文字或图片。设置随资料保存、另存为和语言副本保留；旧资料自动使用默认设置，无需数据库迁移。
6. 表格行间距调节单元格内边距，表格文字行距跟随正文行距。正文中的内联颜色、宽高、字号不覆盖 PDF 全局排版，原始 HTML 字段不会因此被修改。

产品语言支持站点已启用的中文、英语、西班牙语、法语、俄语、阿拉伯语、葡萄牙语、印尼语、土耳其语和越南语。阿拉伯语正文为 RTL，拉丁型号、数字及单位隔离方向。缺译不回退中文，也不自动调用付费模型。

已添加产品后切换语言，先保存原稿，再另建独立语言草稿。新稿文字和详情重新读取翻译库，保留选中图片与版式；手动产品保留图片并清空文字，需重新填写。自定义正文不会自动翻译。失败时保持原稿；确认成功后再次保存目标版本。保存列表可按语言筛选。

## 数据边界

- 每份介绍保存为独立副本，产品库之后的修改不会自动覆盖介绍。介绍中的修改也不写回产品库或 PB。
- 存储在管理项目的 `product_brochures` 表，不修改 PB 数据库、栏目、模型字段或模板。接口 `GET/POST /brochures`、`GET/PATCH/DELETE /brochures/:id` 均受登录保护并按当前站点隔离。
- 公司信息读取当前站点，产品导入使用所选语言的现有译文。完整正文中原有的价格和联系方式不会被偷偷删除，发布前请自行核对。正文统一采用 PDF 样式，清除脚本、嵌入视频和网站固定布局。
- 浏览器保留当前站点草稿，但正式留存应点击“保存资料”。清空浏览器存储会丢失未保存的草稿。
- 删除资料或移除图片只删除介绍中的引用，不删除原图文件。已保存介绍中的图片引用会被现有网站资源检测识别。浏览器草稿不属于服务器引用记录。

## 图片和容量

- 每份最多 20 个产品，每个详情正文最多 30 万字符，保存总 JSON 不超过 2MB。独立图片最多 12 张，正文图片参与导出总大小限制；旧版参数最多 100 项，仍可读取和编辑。
- 上传沿用项目现有接口，单张上传上限 5MB。导出允许单张 10MB、总图片 40MB，重复 URL 只读取一次。
- 导出支持 JPG、PNG、WebP、GIF、AVIF、BMP 等位图。外站图片需要允许跨域读取；被跨域或网络问题阻止时，导出会提示失败，可重新上传该图片后重试。
- 图片通过当前站点资源接口读取，网页导出时转为内嵌图片，不含登录令牌。网页导出并不自动发布到公网，也不提供自动生成公网分享链接。
- PDF 请求通过 multipart 上传已分页 HTML（最多 60MB、150 页），不受普通 JSON 接口 10MB 限制；PDF 输出上限 80MB。单进程同时最多 2 个 PDF 任务，繁忙或超时会提示重试，不改动产品资料。
- 后端清理不允许的标签和脚本，只接受内嵌位图；渲染器开启 Chromium 沙箱，禁用页面 JavaScript、网络请求、Service Worker 和下载。并发限制不是公开匿名服务的完整限流方案，接口仍须位于管理端登录及网关保护下。

## 本地与宝塔部署

当前本地已安装 PDF 引擎。新服务器需额外准备：

1. Node.js **22.12 或更高版本**（HTML 安全清理库要求），使用项目锁文件安装后端依赖。Chromium 必须能由实际渲染用户访问，不能只装到 root 的私有缓存而不配置执行入口。
2. 在 `backend` 目录运行 `pnpm exec playwright install chromium`。Ubuntu/Debian 的系统依赖可由管理员运行 `pnpm exec playwright install-deps chromium`；不要通过关闭 Chromium 沙箱来绕过依赖或权限问题。
3. Linux 安装中文字体，例如 Ubuntu/Debian 的 `fonts-noto-cjk`，执行 `fc-cache -f`。系统需要支持 Chromium 沙箱。新部署优先使用非 root 用户；现有 API 为 root 时可只对浏览器降权，不改变整个项目所有权。其他发行版先确认 Playwright 支持情况，必要时单独运行在受支持的容器内，不假定所有宝塔系统相同。
4. 使用自备兼容 Chromium 时，可填写 `BROCHURE_PDF_EXECUTABLE_PATH` 的绝对可执行文件路径。不设置时使用 Playwright 安装的版本。Windows 下不需要更改此项。
5. 宝塔 Nginx 管理端反向代理增加 `client_max_body_size 64m;`、`proxy_read_timeout 180s;`、`proxy_send_timeout 180s;`。仅针对管理 API 配置，不修改 PB 模板、数据库或网站栏目。PDF 生成期间要为 Chromium 预留内存和临时磁盘空间。
6. 当前宝塔使用 `deploy/configure-brochure-chromium.cjs` 配置 `/www/server/pboot-pdf-browser` 和 `pbootpdf` 用户。脚本先真实渲染测试，再备份环境并设置 `BROCHURE_PDF_EXECUTABLE_PATH` 指向 `deploy/chromium-pdf-sandbox.sh`；只在探测成功后重启 API 并 `pm2 save`。脚本针对当前目录布局，其他服务器先审核路径。保留 `chromiumSandbox:true`。
7. 正文图标为方框时检查 Emoji 字体。本次 OpenCloudOS 9 用 `dnf install -y google-noto-emoji-color-fonts`，然后 `fc-cache -f` 和 `fc-match emoji`；不修改原文掩盖问题。
8. 部署后用含中文、横图、竖图和跨页正文的资料实际导出；检查字体、页数、图片和登录权限。本轮已从正式英文 CR1000I 完整字段导出 12 页 A4，未保存业务数据。跨系统字体不同仍需核对 Linux 成品。

## 验证

- 后端：`pnpm --dir backend exec jest --runInBand brochure`。
- 多语言与完整详情：`node --test deploy/brochure-ui.test.cjs`、`node deploy/brochure-browser-check.cjs`。后者使用隔离测试文档，不写业务库；覆盖完整字段、安全清理、缺译、旧资料和四种语言长正文分页，输出桌面/手机检查图至 `.cache-tutorial-update/pdf-check`。
- 生产验收必须点击页面“导出 PDF”并检查下载文件；仅构建、预览或进程 online 都不足以证明渲染器可用。`tools/verify-brochures.cjs` 属于旧版参数表工作流，不作为新版验收命令。
- 新版浏览器检查使用隔离 fixture，覆盖真实 /api 相对图片代理、完整正文、保留原文表格但不自动提取参数、十种语言标签、四种语言长文分页、正文开关和旧稿兼容，不写真实产品、不调用 AI。
- Jest 对 ESM 的 HTML 解析器依赖使用定向转换，以测试真实安全清理逻辑；生产环境依赖 Node.js 原生 ESM 支持。
# 2026-09-12 预览卡住与超时提示修复

- 普通接口超时不再提示“翻译中断”，也不推断后台已停止。保存超时先核对已保存记录，避免重复提交。
- 文档 iframe 内给动画帧、空闲回调增加定时器兜底，避免隐藏或离屏预览无限等待。主后台不替换这些 API。
- 图片按地址合并预加载，同一时间最多加载 3 个地址；单次 15 秒，失败自动重试一次，整体图片队列最多 60 秒。进度显示完成数量及重试状态。队列失败或超时后停止剩余加载，不漏图继续导出。
- 图片解码、字体、分页分别有 10/15/60 秒超时；父页面及离线导出有 150 秒兜底及重新排版按钮。失败停止并移除不完整预览，保留原稿。
- 编辑模式不启动分页；重新显示时生成新预览。代次标识阻止旧任务覆盖新结果；导出忽略进度消息，只处理最终结果。
- 先恢复浏览器草稿，再读取站点资料；初始化失败或缓存不合法时不覆盖旧缓存。
- 前端专用发布参数 `--frontend-only` 不重启后端或其他工具，不改变数据库。
