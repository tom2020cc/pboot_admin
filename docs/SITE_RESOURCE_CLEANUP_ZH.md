# 网站资源检测（保守试用版）

入口：站点管理 → 资源检测，始终跟随顶部选中的网站项目。

## 操作

1. 扫描资源，查看状态和判断依据。
2. 默认不选中任何文件。只有“未发现引用”的图片、真正的空目录可以勾选，每批最多 200 项。
3. 确认后移入隔离区，不提供永久删除按钮。
4. 在“隔离记录”中恢复。原路径已有文件时跳过，不覆盖。

隔离位置是后台运行账户的用户目录下 `.pboot-admin-resource-quarantine/<站点ID>/<批次ID>`，不在网站目录内。
关闭页面或重启后台不会丢失隔离记录；扫描结果在 30 分钟后、重启后或重新扫描后失效。

## 宝塔部署准备

先在本地用测试数据验证，部署后再由操作人员扫描真实站点，不迁移本地扫描结果。

- 后台 `.env` 设置 `RESOURCE_QUARANTINE_ROOT=/www/backup/pboot-resource-quarantine`，必须使用绝对路径且位于所有网站根目录外。
- 给实际运行 Node 的用户授予该目录读写权限，以及目标网站 `static` 的读写权限；不要使用 `chmod 777`，不要求必须以 root 运行。
- 隔离采用复制校验后移除源文件，支持 Windows 不同盘符及 Linux 不同挂载卷。
- 使用单个后端进程，部署示例已显式设置 PM2 `instances: 1`，避免 SQLite 写盘和清理任务同时跨进程执行。
- Nginx 保留 `/api/` 反向代理前缀，前端配置 `VITE_API_BASE_URL=/api`。既有部署示例已为长请求设置超时。
- 新网站档案使用真实 Linux 路径，例如 `/www/wwwroot/shanbo-rig.com`；不把本机 `E:/...` 路径原样当作服务器路径。
- 正式部署仍需验证账户权限、磁盘空间、HTTPS、反向代理和恢复能力。本地测试不能替代真实服务器验收。

## 判断范围

- 只允许处理当前站点 `static` 内的图片与空目录，程序、模板、数据库、文档等不清理。
- 检查 PB 全部表及全部语言，包括扩展字段、幻灯片和配置。
- 检查项目数据库全部实体的保存内容，包含未同步的内容；跨站公共引用也保守保护。
- 检查网站模板、静态 HTML/CSS/JS/SVG 等文本、配置目录和网站根部文本入口。
- 支持编码路径、JSON 路径、相对路径、单独文件名引用。同名文件可能一起被保护。
- 目录路径、模板变量、图片扩展名拼接等动态线索标记待确认，不能勾选。
- 最近 7 天创建、修改或文件属性变更的图片不开放清理，保护刚上传但尚未保存的内容。

**“未发现引用”不是“确认无用”。** 不执行 PHP，也不破解或解析 CMS 加密运行代码；远程接口、外部链接、浏览器未保存草稿及无任何静态线索的动态地址不能保证完整识别。首次使用应少量隔离，并检查网站页面后再处理下一批。

遇到链接目录、无法读取的引用数据、不支持的文本编码或扫描上限，扫描失败并关闭本次清理入口，不返回不完整的可清理列表。
PB 数据库必须位于所选站点的真实 `data` 目录；存在未合并 WAL 或活动事务日志时也会停止，防止漏读刚保存的引用。
清理前重新扫描引用并比对文件摘要；站点、目录、引用或文件变化时停止。复制备份并校验后才移除源文件，空目录只执行非递归删除。
中途中断可从已写入的隔离清单恢复，隔离文件被修改时拒绝恢复。

## 验证

`backend/src/sites/site-resource*.spec.ts` 使用临时网站、数据库和隔离目录测试，不操作真实数据。
`tools/verify-site-resources.cjs` 使用完全模拟的写入 API 验证页面交互。
